# Spec: Walk Presence Markers (маркеры прогулок на мировом масштабе)

## Problem Statement
На экране Personal Heatmap при zoom < 10 (Heatmap Visibility Cutoff) история прогулок не отображается вообще. Отдалив карту до масштаба страны или мира, пользователь видит пустую карту и не понимает, где у него были прогулки и куда приближаться за деталями.

## Solution
Ниже zoom 10 вместо heatmap отображаются **Walk Presence Markers** — небольшие светящиеся точки CyanGhost, сгруппированные в **Presence Clusters** по экранной сетке 64dp. На каждом кластере — число прогулок (включая «1»), радиус растёт логарифмически с количеством. Тап по кластеру выполняет **Cluster Drill-Down** — анимированный зум к объединённым границам его прогулок (зум в пределах [10, 16]), где сразу проявляется heatmap. На zoom ≥ 10 маркеры скрыты, работает только heatmap; полосы перекрытия нет.

## User Stories
1. Как пользователь, я хочу при отдалении карты ниже zoom 10 видеть точки там, где гулял, чтобы сразу понимать географию своих прогулок.
2. Как пользователь, я хочу, чтобы близкие прогулки объединялись в один маркер с числом, чтобы карта не превращалась в кашу из наложенных точек.
3. Как пользователь, я хочу видеть число даже на одиночном маркере («1»), чтобы единообразно читать карту.
4. Как пользователь, я хочу, чтобы маркер места, где я гуляю часто, был крупнее, чтобы без чтения цифр видеть «домашние» районы.
5. Как пользователь, я хочу, чтобы при приближении кластеры распадались на более мелкие, чтобы постепенно уточнять места.
6. Как пользователь, я хочу по тапу на кластер плавно приблизиться к его прогулкам, чтобы попасть к детальному heatmap в одно касание.
7. Как пользователь, я хочу, чтобы drill-down к одиночной короткой прогулке показывал её маршрут (не ближе zoom 16), а к кластеру размером со страну — останавливался на zoom 10, чтобы heatmap был виден всегда.
8. Как пользователь, я хочу, чтобы на zoom ≥ 10 маркеры исчезали и оставался только heatmap, чтобы слои не путались.
9. Как пользователь, я хочу, чтобы маркер стоял в центре маршрута, а не в точке старта, чтобы он честно отражал место прогулки.
10. Как пользователь, я хочу, чтобы прогулки без трека (меньше 2 точек) не создавали ложных маркеров.
11. Как пользователь без прогулок, я хочу видеть пустую карту без ошибок.
12. Как пользователь, я хочу, чтобы маркеры соответствовали OLED-неоновой стилистике (Two-Pass Glow), чтобы экран выглядел цельно.
13. Как пользователь, я хочу, чтобы панорамирование и зум на мировом масштабе оставались плавными даже при сотнях прогулок.

## Implementation Decisions
- **Данные (без миграции)**: новый запрос `WalkDao.getWalkAnchors()`:
  `SELECT walkId, (MIN(latitude)+MAX(latitude))/2 AS lat, (MIN(longitude)+MAX(longitude))/2 AS lon, MIN(latitude) AS minLat, MAX(latitude) AS maxLat, MIN(longitude) AS minLon, MAX(longitude) AS maxLon FROM track_points GROUP BY walkId HAVING COUNT(*) >= 2`.
  Результат — `WalkAnchor(walkId, lat, lon, bounds)`; bounds нужны для drill-down. Прокидывается через `WalkRepository`.
- **Domain `domain/heatmap/PresenceClusterer`** (чистый Kotlin, без Android):
  - `cluster(anchors, zoom, cellSizePx): List<PresenceCluster>` — проекция якорей в мировые пиксели через `WebMercatorProjection` при текущем zoom, группировка по ячейкам `floor(px / cellSizePx)`; центр кластера — среднее проекций; при `zoom >= HeatmapVisibilityCutoff (10)` возвращает пустой список.
  - `PresenceCluster(center, count, walkIds, bounds)` — bounds = объединение bbox прогулок.
  - `drillDownTarget(cluster): Pair<BoundingBox, zoomClamp>` — объединённый bbox; итоговый zoom ограничен [10, 16].
  - `markerRadiusDp(count)` — `8 + 6 * log(count)/log(cap)`, кламп [8, 14] dp.
  - Константа cutoff — единый источник с `HeatmapTileProvider.MIN_HEATMAP_ZOOM`.
- **ViewModel**: `HeatmapUiState` получает `walkAnchors: List<WalkAnchor>`; заполняется один раз при входе на экран вместе с `loadRecentBounds()` (без подписки на Flow).
- **UI**: кастомный osmdroid `Overlay` (`PresenceMarkersOverlay`) в `ui/heatmap/components/`, рисует все кластеры в `draw()`; кластеры пересчитываются по завершении зума/скролла (`MapListener` с debounce), а не на каждый кадр анимации. Обработка тапа — `onSingleTapConfirmed` с хит-тестом по радиусу → `zoomToBoundingBox` с паддингом и последующим клампом зума [10, 16].
  Видимость: overlay рисует только при `mapView.zoomLevelDouble < 10`; heatmap tile overlay остаётся как есть (min zoom 10).
- **Визуал**: Two-Pass Glow — полупрозрачная аура CyanGhost + яркое ядро; число — белый/чёрный bold текст по центру; «99+» для больших чисел.
- **Документация**: Glossary и ADR-0003 (Amended) уже обновлены.

## Testing Decisions
- Хороший тест проверяет наблюдаемое поведение (число кластеров, счётчики, центры, целевой bbox/zoom), а не внутренние структуры.
- **Основной шов — `PresenceClusterer` (pure JVM)**, по образцу `WebMercatorProjectionTest`:
  - две близкие прогулки при низком zoom → 1 кластер count=2; при более высоком zoom → 2 кластера;
  - далёкие прогулки (Москва/Берлин) → разные кластеры на zoom 3;
  - zoom ≥ 10 → пустой результат; пустой вход → пустой результат;
  - drillDown одиночной короткой прогулки → zoom 16 (кламп сверху); кластер континентального размера → zoom 10 (кламп снизу);
  - `markerRadiusDp`: 1 → 8, монотонный рост, кламп 14.
- **Вспомогательный шов — `WalkDao.getWalkAnchors()`** (Room in-memory, Robolectric, по образцу `WalkDaoSpatialTest`): центр bbox корректен; прогулки с 0/1 точкой исключены.
- **Вспомогательный шов — `HeatmapViewModel`** (фейковый репозиторий, по образцу `HeatmapViewModelTest`): якоря появляются в `uiState`; `@JvmOverloads`-конструктор сохраняется.
- **Визуальная проверка** в эмуляторе (скриншоты zoom 3/9/10, тап drill-down) — пиксельная отрисовка не тестируется на Windows JVM (Skia ограничение).
- Прогон: `.\gradlew.bat testDebugUnitTest`, `pwsh scripts/check_localization.ps1`, `pwsh scripts/check_android_compat.ps1`.

## Out of Scope
- Группировка по городам/регионам через геокодер.
- Хранение якорей в таблице `walks` (миграция Room).
- Живое обновление маркеров при появлении новых прогулок, пока экран открыт.
- Bottom sheet / список прогулок по тапу на кластер.
- Полоса перекрытия heatmap и маркеров на zoom 10–11.
- Отображение маркеров на других экранах (Home, Active Walk).
- Accessibility / озвучка маркеров экранным диктором (TalkBack).

## Further Notes
- Если агрегат на тысячах прогулок станет узким местом — путь эволюции: денормализованные колонки якоря в `walks` (миграция v2→v3).
- Пересчёт кластеров O(n) на событие зума; при n ≤ несколько тысяч — без фоновых потоков.
- Тексты на маркерах — только цифры; новых UI-строк фича не добавляет.
